## 1. 产品背景、定位与目标

### 1.1 背景

个人在工作中同时使用待办、会议录音、笔记、资料收藏、翻译和日历。实际问题不是缺少记录入口，而是内容收集之后仍需要重复整理：会议中的承诺没有进入任务列表，随口想到的事情容易忘记，收藏资料缺少背景，待办数量增加后难以确定每天可执行的安排。

需求提出者明确表示，会后整理、临时想法遗忘、收藏后难找、任务难安排这四类问题均存在。本次需求依据为个人使用反馈，没有独立的用户访谈样本、量化耗时基线或市场规模数据。

### 1.2 产品定位

**拾序是一个常驻 Mac 屏幕顶部、以待办为中心的个人工作台。**通过文字、语音、录音和截图获取信息，由主助手辅助结构化整理，重要操作经用户确认后执行。

工作台同时保留笔记、链接、音乐、番茄钟、镜子、密钥等个人工具。常用功能可以低成本唤起，完整资料仍可在各自页面查看。

### 1.3 用户价值与目标

| 问题 | 产品目标 | 用户获得的结果 |
|---|---|---|
| 临时想法容易忘 | 降低捕捉成本，允许先保存后分类 | 不必打断手头任务就能留住信息 |
| 会后整理耗时 | 把转写整理成摘要、决定、问题和行动项 | 不必反复听完整录音寻找任务 |
| 待办太多难安排 | 结合预计耗时、截止日期和日历生成安排 | 清楚哪些事今天放得下、哪些需要调整 |
| 收藏资料后难找 | 先保留独立笔记、链接与录音管理，并为资料找回保留演进方向 | 0.2.0 可分类查看；跨类型统一搜索仍待建设 |
| 工具切换频繁 | 保留贴顶入口、快捷键和轻量工具区 | 常见动作可在工作台内完成 |

### 1.4 为什么使用 AI

明确的文字日期解析、时间冲突判断、重复写入防护适合由程序规则完成；口语任务理解、会议摘要、行动项提取和翻译需要处理开放语言，因此使用模型辅助。

模型输出只作为候选结构与文本。主程序负责校验、展示预览和执行。不能以“模型认为合理”作为写入任务或日历的充分条件。

### 1.5 成功指标（建议，尚无基线）

建议核心指标为**每周完成的有效整理闭环数**：一次输入最终由用户确认转为待办、笔记、日历安排或明确归档，且未因识别错误立即撤销，计为一个闭环。同一来源的重复点击不重复计数。

配套观察会议整理耗时、行动项采纳率、快速记录留存率、日程写入成功率与修改/撤销原因。个人试用阶段先记录真实基线，再决定提升目标；当前没有宣称已节省多少时间。

## 2. 用户与核心场景

### 2.1 目标用户

首要用户是使用 Mac 进行产品、设计、研究、开发或知识工作的个人，需要同时处理会议、临时事项和资料。产品当前无团队成员体系、组织后台、协作分配或 SaaS 账户要求。

“会议中的负责人”是内容信息，不是系统账号。把行动项加入自己的待办，表示自己负责执行或跟进，不会通知原文中的其他人。

### 2.2 用户故事

| ID | 用户故事 | 完成条件 |
|---|---|---|
| US-01 | 工作中想到一件事，按住快捷键说出来 | 松开后出现可检查的待办预览，确认后保存 |
| US-02 | 还没想好如何分类，希望先记住 | 内容进入「待整理」，重启后可找回 |
| US-03 | 开会时希望快速开始与结束录音 | 快捷键切换录音状态，音频保存在录制页 |
| US-04 | 会后希望得到真正需要跟进的事情 | 摘要、决定、问题和行动项分开呈现，行动项可查看原文依据 |
| US-05 | 希望知道今天的任务是否做得完 | 填写预计耗时后，得到无日历冲突的候选安排或无法安排的原因 |
| US-06 | 希望在 Mac 自带日历看到任务安排 | 确认写入后，事件出现在选定日历中，可再次改期 |
| US-07 | 阅读英文截图时需要复制或理解 | OCR 后可编辑、复制；配置模型后可译为中文 |
| US-08 | 希望原有个人工具继续可用 | 顶部导航可查看笔记、链接、录音，首页保留次级工具 |

- 每日三件重点、自动日报/周报、长期偏好学习。
- 自动从一句话跨会议整理与每日安排连续规划、运行多个后台 Agent。
- Apple 提醒事项同步；Apple 日历双向同步；日历自动跟随任务完成/删除。
- 系统音频或会议软件远端音轨直接捕获、说话人分离、时间戳定位原音频。
- 唤醒词、永久监听、无确认批量执行、自动联系其他人。
- Intel Mac/Windows 的本期安装交付、云端多设备同步、团队协作。

以上可以作为后续方向，但不得以 0.2.0 已支持进行宣传。

## 4. 信息架构与界面

### 4.1 页面结构

```text
拾序：屏幕顶部入口 / 菜单栏
├─ 首页
│  ├─ 一句话输入：说一句 / 存到待整理 / 理解并预览
│  ├─ 我的待办 / 处理结果 / 操作记录 / 待整理
│  ├─ 会议整理 / 每日安排
│  ├─ 日历连接与日程摘要
│  └─ 次级工具：录音、随笔、音乐、番茄钟、当前窗口、镜子等
├─ 待办：完整任务管理
├─ 笔记：列表、搜索、编辑
├─ 链接：收藏管理
├─ 录制：音频、转写、会议整理入口
├─ 识字翻译：图片输入、原文、译文
├─ 密钥：右上角入口
└─ 设置：右上角入口
   ├─ 语音与录音快捷键
   ├─ API 与转写配置
   ├─ 页面/工具显隐及默认页
   └─ 原有启动、数据等设置
```

可选剪贴板功能沿用原实现，默认不突出展示。「待整理」当前是首页弹层入口，不是新增的顶部一级标签。

### 4.2 首页布局要求

- 左侧主区承载输入、待办列表和处理结果；右侧保留可滚动工具区。
- 顶部导航按屏幕空间排列，兼顾物理刘海，不把按钮放到不可点击区域。
- 密钥、设置图标必须有可访问名称与悬停说明。
- 弹层包含标题、关闭入口、可滚动内容和明确状态反馈；支持键盘焦点与 Escape。
- 清楚区分“预览完成”“本地已保存”“已写入日历”，不能只用一个含糊的“完成”。
- 镜子未启动时显示中性占位图，只有主动点击才调用摄像头；离开首页或收起时释放。

### 4.3 当前界面参考

当前界面为深色。桌面测试截图保留在本地验收资料中，不包含在此发布文档；会议与日历测试使用模拟响应。





## 5. 核心流程

### 5.1 语音到待办

```text
启用并配置快捷键
→ 按住快捷键
→ 检查是否已有录音、转写配置和麦克风权限
→ 开始录音并显示状态
→ 松开快捷键
→ 停止采集、完成转写
→ 解析成候选操作
→ 用户查看任务、日期及匹配对象
→ 逐条确认
→ 写入本地待办与操作记录
→ 可选：打开日历安排窗口，另行确认写入
```

提前松开、权限失败或已有录音时，不得留下后台继续录音。识别不明确时保留文本，用户修改后重试。

### 5.2 临时记录到整理

```text
输入临时想法 / 资料文字 → 存到待整理 → 稍后打开
  ├─ 提取待办 → 预览 → 确认 → 正式待办
  ├─ 存为笔记 → 笔记页可查看
  ├─ 查看原录音 / 发起会议整理
  └─ 移出待整理 → 只移除列表条目
```

### 5.3 会议到行动项

```text
开始录音 → 结束保存 → 录制页 / 待整理
→ 打开会议整理，检查转写
→ 模型生成结构化结果
→ 程序核对格式与行动项原文依据
→ 结果保存到待整理
→ 用户确认标题、负责人和截止日期
→ 加入个人待办
→ 可选择日历安排或稍后进入每日安排
```

### 5.4 待办到每日安排

```text
选择日期与工作时段 → 勾选任务 → 填写预计耗时
→ 读取日历忙碌时段
→ 按截止约束寻找连续空闲时间
→ 展示安排建议 + 未安排原因
→ 用户确认某条安排
→ 再次检查日历冲突、任务变化与时段是否已过去
→ 创建或更新关联日历事件
```

当前两个流程由按钮显式进入；“会议整理完成后自动调用每日安排”尚不是已实现的自动调度能力。

## 6. 功能需求详述

### 6.1 FR-01 桌面入口与导航

**需求**：应用常驻顶部与菜单栏，既能快速进入，又不长期占用桌面空间。

**规则**：保留原展开/收起机制、面板唤出快捷键、页面显隐及默认打开页。首次使用可以只操作本地文字任务，不要求先配置全部权限或 API。新增录音快捷键不能抢占已配置的面板唤出快捷键。

**验收要求**：

- [ ] 展开、收起、切页及重新启动均正常；隐藏页面不破坏保存的数据。
- [ ] 首页、待办、笔记、链接、录制、识字翻译及右上角入口可达。
- [ ] 无 API 时仍可完成明确文字待办、笔记和基础本地操作。
- [ ] 缩放、多屏与物理刘海边界不出现不可操作按钮；多屏为待实测范围。

### 6.2 FR-02 待办与事务预览

**入口**：首页输入区、按住说话、待办页、笔记/录音/OCR 的提取入口。

| 字段/操作 | 规则 |
|---|---|
| 原始输入 | 首页最多 8,000 字；空文本不提交 |
| 任务标题 | 候选任务须有明确内容；会议行动项标题限制见 FR-06 |
| 截止日期 | 可空；日期与精确时刻区分。新语音/文字提取没有日期时，不补造截止时间 |
| 分类 | 使用原待办分类体系；内部 P0–P3 不代表本 PRD 优先级 |
| 操作类型 | 新增、查询、修改、完成；重复规则等不支持意图应提示 |
| 目标匹配 | 多个候选须由用户选择；不得随机修改同名任务 |
| 预览确认 | 原始任务在预览后改变时，阻止旧预览覆盖新状态 |
| 撤销 | 首页操作记录支持局部撤销；当前任务又被编辑时阻止覆盖 |

**日期兼容说明**：原手动新增页面沿用上游默认日期行为；语音/模型提取支持无日期。当前并未统一重写所有旧页面的日期交互。仅给日期不补造具体提醒时刻是助手解析要求，不应被描述为所有旧入口已经完全一致。

**验收要求**：

- [ ] “明天交房租；健身”拆分为两条，健身保持无截止时间。
- [ ] “健身改到后天，房租已完成”对已有任务生成相应操作。
- [ ] 同名未完成任务阻止重复创建；连续点击同一确认不重复执行。
- [ ] 预览期间任务被编辑、删除时，执行前反馈变化。
- [ ] 撤销只恢复对应本地操作，不声称回滚已创建的日历事件。

### 6.3 FR-03 全局语音与会议快捷键

**入口**：设置 → 语音与录音快捷键。

| 配置项 | 类型 | 默认值 | 校验 |
|---|---|---|---|
| 启用语音待办 | 开关 | 关闭 | 只有用户启用后监听 |
| 语音待办组合键 | 按键捕获 | Control+Option+Space | 至少含 Command/Control/Option 之一，可附加 Shift |
| 启用会议录音 | 开关 | 关闭 | 独立配置 |
| 会议录音组合键 | 按键捕获 | Control+Option+R | 与语音及面板唤出组合不冲突 |
| 主键 | 枚举 | 用户选择 | A–Z、0–9、Space、F1–F12 |
| 保存结果 | 状态 | 未启用/已启用/失败 | 权限或注册失败时回滚，不留下半生效配置 |

**语音状态**：空闲 → 启动中 → 录音中 → 结束转写中 → 操作预览/失败。松开可发生在任意启动阶段，必须记录停止意图。单段语音待办上限为 2 分钟。

**会议状态**：空闲 → 按一次开始 → 录音中 → 再按一次结束 → 保存。键盘自动重复不得反复开停。已有录音时不另开第二段；停止已有会议应优先于禁止新录音的弹窗规则。

**验收要求**：

- [ ] 在其他应用前台按键，也能启动对应动作；必须用实体键盘实测。
- [ ] 按下后立即松开、先松修饰键、长按重复均能正确结束，不残留录音。
- [ ] 会议第二次按键只结束当前录音；不受会议整理弹窗阻挡。
- [ ] 系统权限拒绝、组合占用、监听进程退出时有反馈，保留有效旧配置。
- [ ] 锁屏、睡眠、退出停止采集；退出尽力完成录音保存，超时不能伪报成功。
- [ ] 配置输入框、API 弹窗中的按键不意外开启新的麦克风采集。

### 6.4 FR-04 待整理

**定义**：本机待归类内容列表，不是邮箱，不订阅外部消息，也不会自动读取邮件。

**来源**：首页文字记录、非语音待办录音、会议整理结果。原链接收藏页继续独立使用；保存一个网页链接不等于自动进入跨应用资料收集流程。

**规则**：

- 当前最多保存 300 条待整理内容，达到上限提示用户先整理，不静默淘汰旧内容。
- 每条包含唯一标识、类型、内容、创建时间，可带原录音来源及会议结果。
- 普通文字可提取待办或转笔记；会议结果可查看并逐条确认行动项。
- 存为笔记成功后移出该待整理条目；提取待办不自动删除原内容。
- 移出条目不删除原录音、已创建任务或日历事件。
- 0.2.0 列表摘要展示前 180 字，没有通用的长文本全文编辑器；这是后续应补齐的可用性缺口。
- 无转写录音的提示文本不应被当作真实会议内容；用户应打开原录音补充转写后整理，该分支需专项试用核验。

**验收要求**：

- [ ] 保存后、切页后、重启后均可找回内容。
- [ ] 录音保存和会议结果同时进入时不互相覆盖。
- [ ] 转笔记成功才移出；失败时保留原内容。
- [ ] 达到容量上限明确提示，不自动删除资料。
- [ ] 移出条目不会误删其来源文件或派生任务。

### 6.5 FR-05 录音与转写

**入口**：首页快速录音、录制页、会议录音快捷键。

**能力**：开始、暂停、继续、结束保存、回放、编辑标题与转写、复制转写、显示文件、删除录音。保存音频与转写分开处理：无转写不等于音频失败。

**音源边界**：当前是麦克风录音。戴耳机参加在线会议时，远端声音可能不会进入麦克风录音；不承诺完整记录系统声音。没有说话人分离，也不提供点击句子跳转音频时间点。

**服务依赖**：百炼 Qwen 实时转写需要有效 Key 与地域配置；未配置时仍可尝试录音保存，但不能保证自动转写。用户可补充文字后再整理会议。

**验收要求**：

- [ ] 结束和退出后释放音频轨道，不继续采集。
- [ ] 保存成功有可回放音频；写入失败必须显示失败。
- [ ] 转写失败时仍说明音频是否保存，并提供手动补充途径。
- [ ] 一段会议通过快捷键、页面按钮混合操作，状态仍一致。
- [ ] 本地讲话、会议扬声器、耳机三类真实场景分别核验音源覆盖，不混为一项通过。

### 6.6 FR-06 会议整理专业流程

**入口**：首页「会议整理」、录制详情「会议整理」、待整理中的录音或已保存会议结果。

**输入**：会议转写文本、来源类型/标识、当前待办列表、当前时间与时区。文本可编辑后重新提交。

| 字段 | 类型/范围 | 必填规则 |
|---|---|---|
| 转写文本 | 文本，1–60,000 字符 | 必填；空文本不调用模型 |
| 摘要 | 文本，最多 8,000 字符 | 模型必须提供有效内容 |
| 决定 | 字符串数组，最多 30 条 | 可为空；不能把讨论建议当已决定 |
| 待确认问题 | 字符串数组 | 模型初始最多 30 条；程序可追加证据缺失提示 |
| 行动项 | 数组，最多 40 条 | 可为空 |
| 行动项标题 | 文本，1–80 字符 | 必填，可由用户修改 |
| 负责人 | 文本或空，最多 80 字符 | 无原文依据不自动指定 |
| 截止日期 | 日期、日期时间或空 | 无日期依据则为空；用户可补充 |
| 预计耗时 | 0 或 1–480 分钟整数 | 0 表示未知；自动提取须有证据 |
| 原文依据 | 文本，1–2,000 字符 | 必须在转写中逐字匹配 |
| 来源 | recording / note / text 与来源 ID | 系统关联，不允许模型虚构 |

**输出与确认规则**：

1. 展示摘要、已明确决定、待确认问题、行动项，不合并成一段无法操作的总结。
2. 行动项必须具有连续原文引用。日期、负责人、耗时还需对应片段支持；没有依据的字段不补造。
3. “证据片段存在”只证明出处可定位，不证明日期推断或责任理解一定正确，因此仍需用户确认。
4. 整理成功先保存到待整理，即使用户已关闭弹层，也应提示结果保存位置。
5. 点击“确认由我跟进，加入待办”后才写入本地任务。不会自动给原文负责人发消息或分配系统账号。
6. 保存行动项来源与已执行记录，重启后不应重复加入。当前防重复主要为同名匹配，不是全面语义去重。
7. 摘要可单独存为笔记，任务可继续选择日历安排。
8. 当前长文本是单次模型请求，没有自动分段/合并。60,000 字符上限不是长会议效果保证。

**验收要求**：

- [ ] 输入只有讨论建议时，不捏造明确承诺或任务。
- [ ] 原文不存在的行动项证据被拦截；模型失败不展示假摘要。
- [ ] 无负责人/日期时为空或提示确认，不默认设为用户/当天。
- [ ] 用户修改后确认的标题和日期按修改值保存。
- [ ] 同名任务与重复点击不产生重复待办；重启保留确认记录。
- [ ] 关闭弹层后完成的结果仍能在待整理找到。

### 6.7 FR-07 每日安排专业流程

**入口**：首页「每日安排」。

| 字段 | 默认/限制 | 规则 |
|---|---|---|
| 安排日期 | 默认本地今天 | 单日安排，必须为有效日期 |
| 工作开始/结束 | 09:00–18:00 | 同一天，结束晚于开始；用户可修改 |
| 候选任务 | 当前未完成任务，界面最多 100 条 | 用户勾选；有本地日历关联的默认不勾选 |
| 预计耗时 | 采用已有值或用户输入 | 每项 1–480 分钟；无值不猜测 |
| 日历事件 | 当天可读的忙碌事件 | 读取失败停止排程，不能假设空闲 |
| 结果 | 时间建议、未安排原因 | 只展示预览，不自动写入 |

**排程规则**：

- 由确定性规则计算，不需要模型自由生成时间。
- 先按截止时间排序；无截止日期的任务排在有截止约束的任务之后。
- 避开读取到的忙碌时段，包括被视为忙碌的全天日程；候选安排之间也不得重叠。
- 每项任务需要一个连续时间块，本期不拆分任务，不优化多天计划，不自动插入午休/缓冲。
- 不安排到过去；已逾期任务要求用户先明确新的截止日期。
- 没有足够连续空闲时段时，明确解释，不压缩用户填写的耗时。
- 确认前重新读取目标时段，检查冲突和任务是否变化，防止旧预览直接写入。
- 用户再次选择已关联任务时，可以通过确认调整原事件；无双向同步，因此外部变化以实时日历读取为准，本地关联提示不是最新日历事实的保证。

**验收要求**：

- [ ] 给定任务与日历输入，相同规则产生可复现安排。
- [ ] 任务不超过工作时段和截止时间，不与其他建议重叠。
- [ ] 缺耗时、全天占用、时段已过去或已逾期时返回可理解原因。
- [ ] 预览后新增日程占用同一时段，确认时阻止写入并要求重算。
- [ ] 生成建议本身不创建任何日历事件。

### 6.8 FR-08 Mac 日历写入与改期

**产品解释**：「拾序」日历是 Mac 自带日历 App 内的一个分类，不是另开发一个日历应用。

**入口**：任务行「日历」、任务确认后的「加入日历 / 改期」、每日安排建议。

| 字段 | 必填 | 规则 |
|---|---|---|
| 任务 ID | 是，系统提供 | 关联本地任务，不能以标题作为唯一键 |
| 日历标题 | 是 | 默认任务标题，写入层限制 1–500 字符 |
| 开始/结束 | 非全天时必填 | 有效时间，结束大于开始 |
| 全天选项 | 否，默认关闭 | 用户主动选择；使用本地日期和次日边界 |
| 全天日期 | 全天时必填 | 不把仅有截止日期的任务自动转成全天事件 |
| 目标日历 | 是，提供默认选项 | 默认按需创建/复用「拾序」，或选择现有可写日历 |
| 写入确认 | 是 | 明确点击后才执行 |

**一致性规则**：

- 截止日期表示“最晚何时完成”；日历时段表示“何时实际执行”。保存或调整日历不得修改任务截止日期。
- 同一任务重复保存应更新原事件；修改标题后仍按任务 ID 关联。
- 本地持久化写入意图与事件关联；网络/响应失败后重试先恢复或核查关联，避免重复创建。
- 事件被用户删除、归属标记变化或发现重复关联时，显示问题，不擅自重建或覆盖其他事件。
- 选择其他日历时检查可写性；没有可用账户时提示先配置 Mac 日历。
- 本期不把本地完成、删除、撤销映射为日历删除；在日历中的直接修改也不反向更新任务。
- 每日安排确认会重查冲突；手动日历窗口按用户明确填写的时间保存，目前不是统一的自动冲突阻断入口。UI 应说明这一差别，后续可补手动冲突提示。

**验收要求**：

- [ ] 首次确认后在 Mac 日历中看到事件，颜色与分类可由系统管理。
- [ ] 重复确认、重启后重试、同任务改期均不增加重复事件。
- [ ] 同标题不同任务不会互相覆盖。
- [ ] 全天天数与当地时区正确，跨月、夏令时和系统时区变更需要专项测试。
- [ ] 关联异常时不静默写入另一事件；界面区分本地任务已保存与日历写入失败。
- [ ] 明确说明单向写入边界，完成任务不让用户误以为日历事件已经删除。

### 6.9 FR-09 截图 OCR 与翻译

**入口**：顶部「识字翻译」、首页截图识字入口。

**主流程**：框选截图/打开图片/读取剪贴板图片 → Apple Vision 本地识字 → 原文可编辑 → 复制、翻译、存为笔记或提取待办。

**规则**：

- OCR 在本机执行，支持中英文文字；不能承诺复杂表格排版、手写体或低清图完全还原。
- 框选过程中可按 Escape 取消，取消不覆盖已有原文。
- 翻译使用用户配置的模型；只发送提取/编辑后的原文，当前翻译文本最多 12,000 字符。
- 自动翻译必须由用户勾选；原文变化时清除过期译文。
- 复制结果应能粘贴到其他应用；无内容时不显示虚假成功。
- OCR 原文转笔记时不能覆盖尚未保存的随笔草稿。

**验收要求**：

- [ ] 图片、截图、剪贴板三种入口产生可编辑文本。
- [ ] 测试英文图识别内容与复制结果一致。
- [ ] 未配置模型、网络失败、文字为空时给出对应反馈。
- [ ] 修改原文后不把旧译文继续当作新结果。
- [ ] 截图取消或识别失败保留之前可用内容。

### 6.11 FR-12 设置、配置与升级

- [ ] 未授予某项权限时，其他独立本地功能仍可用。

## 7. 主助手与 AI 能力

### 7.1 架构定义

当前采用**一个主助手入口、两套显式专业流程、共享工具与数据**。它是受控工作流实现，不是模型可任意调用工具和持续自主运行的通用 Agent。

```text
用户输入 / 页面动作
        ↓
主助手流程调度（meeting / daily）
        ├─ 会议整理：模型抽取 → 结构与证据校验 → 结果预览
        └─ 每日安排：读任务与日历 → 确定性时间计算 → 结果预览
        ↓
用户补充信息与确认
        ↓
受控执行：本地待办 / 笔记 / 日历
        ↓
保存结果、来源与关联；反馈失败或成功
```

语音转写、OCR 与翻译是可复用能力。主助手不需要把它们都包装成独立 Agent。

### 7.2 能力与模型依赖

| 能力 | 实现方式 | 外部依赖 | 失败兜底 |
|---|---|---|---|
| 语音转写 | 百炼 Qwen 实时服务 | Key、地域、网络、音频权限 | 保留音频状态；文字输入/系统听写 |
| 普通事务理解 | 基础中文规则 + 可配置模型 | 复杂表达需要模型 | 保留输入，修改后重试，不自动执行 |
| 会议整理 | OpenAI-compatible 结构化生成 | 用户选择的模型服务 | 明确失败，不生成伪摘要 |
| 每日安排 | 本地规则计算 | 有效日历数据 | 缺数据或无空间时停止并说明原因 |
| OCR | Apple Vision | 本地系统框架 | 提示重截或换图 |
| 英译中 | 配置模型 | 网络与 Key | 保留原文，可复制或重试 |

### 7.3 Prompt 与结构化输出要求

System Prompt 应包含角色、当前时间和时区、明确任务、输出格式、禁止事项与信息缺失策略。用户转写和已有任务以数据传入，内容中的指令不能改变系统规则。

会议流程的核心约束：区分建议、决定和承诺；不补造日期、负责人、耗时；每条行动项提供连续原文引用；只生成待审阅计划，不宣称已经执行。

示例输出结构如下，仅用于说明字段，不代表真实用户数据或默认承诺：

```json
{
  "summary": "讨论了首页改版。",
  "decisions": ["保留暗色界面"],
  "questions": ["方案截止日期需要确认"],
  "actionItems": [
    {
      "text": "整理首页方案",
      "date": null,
      "dateEvidence": "",
      "durationMinutes": 0,
      "durationEvidence": "",
      "owner": "小李",
      "evidence": "小李负责整理首页方案，时间之后再定。"
    }
  ]
}
```

不要求输出或存储模型内部思维链。用户需要看到原文依据、缺失字段和可执行结果。

### 7.4 上下文与工程边界

- 普通事务输入上限 8,000 字符；会议转写 60,000 字符；翻译 12,000 字符。
- 会议/每日流程任务上下文最多 300 条；每日 UI 当前最多展示 100 个候选。
- 当前模型请求超时 30 秒，输出预算 `max_tokens=4096`。这些是代码参数，不是质量或性能承诺。
- 字符数不等于 token 数，模型上下文容量由服务商决定；长会议可能超时或输出截断。
- 当前没有自动切换备用模型、自动分段长会议或服务额度管理。不得在失败时暗中换服务商并外发内容。
- 工作流有并发占用检查；一个整理请求未完成时，应提示等待，避免并发覆盖。

## 8. 数据模型、存储与一致性

### 8.1 核心实体

| 实体 | 核心字段 | 关系/规则 |
|---|---|---|
| Task | id、text、done、category、deadline、datePrecision、durationMinutes、createdAt | 本地任务为事实来源；时间安排单独保存 |
| InboxItem | id、kind、text、createdAt、sourceId、sourceType、result、applied | 关联来源与会议结果；applied 记录已确认行动项 |
| Recording | id、audioPath、mimeType、durationMs、transcript、title、createdAt | 音频为文件，元数据与转写独立保存 |
| Note | id、title、content、createdAt、updatedAt | 可来自随笔、OCR 或会议结果 |
| TaskOrigin | taskId、sourceId、sourceType、evidence、owner | 来源留痕，不等同完整跨模块关系图 |
| Schedule | taskId、start、end、allDay、eventId、calendarId | 执行时间，不覆盖 deadline |
| CalendarLink | scope、taskKey、eventId、calendarId、lookupStarts | 主进程持久化，用于幂等、恢复与所有权验证 |
| OperationJournal | transactionId、taskId、before、after、action、undone | 首页本地操作撤销，当前最多 60 条 |
| ShortcutConfig | voice/meeting 的 enabled、accelerator | 与原面板快捷键独立但互相校验 |

### 8.2 存储策略

- 继续使用 `~/Library/Application Support/Mac Voice Workspace/`，避免更名造成数据割裂。
- 任务、笔记、待整理等使用本地页面存储并通过工作区快照保存；录音使用相对文件路径。
- 日历关联由主进程单独持久化，配置写入按模块处理；密钥使用系统安全存储加密。
- 用户内容并非全部加密数据库。不能因为 API Key 加密而宣传所有笔记与录音均加密。
- 本期无云端账户和多设备同步；备份文件复制不能保证系统加密 Key 在另一台电脑可解密。

### 8.3 一致性与删除语义

| 操作 | 影响 | 不应被误解为 |
|---|---|---|
| 移出待整理 | 删除列表中的条目 | 删除原录音、笔记或日历 |
| 完成本地待办 | 修改本地完成状态 | 删除对应日历事件 |
| 撤销首页创建 | 尝试恢复本地任务状态 | 撤销日历写入事务 |
| 改日历时间 | 更新对应事件和本地关联 | 修改任务截止日期 |
| 在 Mac 日历手动编辑 | 改变系统事件 | 自动回写本地任务 |
| 工作区备份失败 | 需区分页面本地保存与备份状态 | 所有资料已经完整备份 |

删除录音后，已存在的摘要与待办可能继续保留，但原录音入口可能失效。应提示来源已不可用，不能自动删除派生工作内容；该分支需补充验收。

## 11. 非功能需求

### 11.1 性能与容量

以下性能值为**建议验收目标，尚未量测达标**：

- 在 macOS 15.1 Apple Silicon 参考机上，热状态展开面板 p95 ≤ 500 ms，本地保存反馈 p95 ≤ 1 s。
- 权限和连接已就绪时，快捷键至录音状态反馈 p95 ≤ 500 ms；首次系统授权单独统计。
- 日常规模 300 条待办、100 个候选任务下，本地排程计算 ≤ 1 s，不计系统日历读取。
- 模型调用使用当前 30 秒超时；超过时限有明确反馈，不把时限当作平均速度承诺。

当前容量：首页待办最多展示 50 条；完整待办页仍可查看其他任务；待整理上限 300；新增笔记入口对 200 条容量进行限制；操作历史最多 60 条。容量超限不能通过静默丢数据解决。不同旧入口的容量行为应在正式版本前统一核验。

### 11.2 可靠性与兼容性

- 当前交付 arm64 DMG；最低系统版本声明不等于所有系统版本都已实测。
- 应用本地签名已验证，未完成 Apple 公证，不按公开正式发行标准宣称已上市。
- 重启恢复关键内容；失败重试具备幂等边界。
- 保留旧数据结构与应用目录；普通升级不清空用户资料。
- 日期使用本地语义、事件存储使用时间戳；日期精度与时区显式处理。

### 11.3 可访问性与可解释性

- 图标入口具备名称；表单具备标签；不只用颜色表达错误或录音状态。
- 弹层可键盘操作，关闭后焦点合理返回；滚动不遮住确认按钮。
- 任务与日历变更展示明确对象和结果；失败时给下一步。
- 页面中不出现面向开发者的内部 API/调试概念，除非用于用户配置或诊断。

## 12. 指标、观测与 AI 评估

### 12.1 观测方案（后续建议，未实施完整埋点）

个人工具优先使用本地、可关闭的事件统计。当前没有已上线的分析后台，本节不要求本次开发额外建立服务端采集。

| 事件 | 触发时机 | 建议字段 |
|---|---|---|
| capture_saved | 内容成功进入待整理 | 类型、入口、成功/失败、耗时 |
| voice_session_finished | 语音结束并得到保存/转写状态 | 结束原因、时长、是否得到文本，不含原音频 |
| meeting_review_ready | 会议结构结果通过校验 | 行动项数、待确认数、耗时、模型标识 |
| action_confirmed | 用户确认一个候选操作 | 操作类型、是否编辑、来源类型 |
| daily_plan_ready | 生成每日建议 | 选择数、安排数、未安排原因类型 |
| calendar_write_finished | 写入明确成功或失败 | 新增/改期、错误类型、耗时，不含事件标题 |
| operation_undone | 用户撤销 | 类型、距执行时长；不要直接推断为模型错误 |

禁止收集 API Key、笔记正文、转写全文、截图、联系人或完整日历标题到通用指标日志。

### 12.2 指标定义

| 指标 | 计算/采样方式 | 用途 |
|---|---|---|
| 有效整理闭环数 | 每周按来源去重的已确认整理数 | 核心价值观察 |
| 行动项采纳率 | 被确认的有效行动项 / 展示的候选行动项 | 观察提取是否有用，需结合人工正确性评估 |
| 会后整理耗时 | 从打开会议整理到完成必要确认的时长 | 与个人手动整理基线比较 |
| 待整理积压 | 当前未处理数量及存放时长 | 检查是否形成新的内容堆积 |
| 日历写入成功率 | 明确成功 / 实际确认尝试；排除用户主动取消 | 评价外部集成稳定性 |
| 语音修订比例 | 用户修改转写/任务的频次 | 区分 ASR 错误、模型理解错误和用户改意图 |

### 12.3 AI 评测集与门槛（建议）

建议先建立 60 条用户授权或合成的代表性样本：20 条口语事务、20 段会议片段、10 组日程约束、10 组 OCR/翻译文本。覆盖多任务、无日期、同名任务、否定、改口、纯讨论、缺负责人、日程冲突和长文本。此评测集尚未建立，不视为现有测试数量的一部分。

| 维度 | 检查方式 | 建议发布门槛 |
|---|---|---|
| 非授权执行 | 不点击确认，核查任务与日历 | 0 次非授权写入 |
| 行动项证据 | 对照连续原文引用 | 展示的引用全部可回查；语义正确性另评 |
| 承诺识别 | 人工标注讨论与真实行动项 | 优先保证精确率，建议 ≥95%；样本数与分母同时报告 |
| 日期/负责人 | 对照原文与用户修改 | 无证据字段不自动补全；不允许把建议变成确定承诺 |
| 排程约束 | 可计算检查开始、结束、冲突、截止 | 所有已确认建议满足硬约束 |
| 幂等与陈旧预览 | 重复点击、重启重试、外部修改 | 无重复副作用，不覆盖变化后的目标 |
| ASR 与翻译 | 真人录音/专业术语人工核查 | 先建立基线，不预设无依据的识别准确率 |

结构校验通过不等于内容正确；模型 JSON 可解析、引用存在与用户真正愿意执行是三个不同层面的指标。

| 多模块分散存储 | 本地成功但备份/外部写入失败 | 分开反馈结果，日历保留持久关联与恢复机制 |
| 上游依赖变化 | Electron/API 或系统升级影响兼容 | 固定版本验证、保留许可证、针对实际升级回归 |

### 14.3 后续需要产品决策的事项

1. 资料找回优先采用关键词统一搜索，还是再引入语义检索；本期不承诺向模型上传全部资料。
2. 是否加入系统音频捕获、转写导入、分段会议和说话人信息。
3. 日历事件随任务完成/删除是否联动；如果加入，需要明确确认、撤销和双向冲突规则。
4. “每天三件重点”、项目关联与工作接续何者先做，应以真实试用痛点选择。
5. 新深色发光应用图标已于 0.2.1 确定；菜单栏继续采用简洁系统模板入口图标。
6. 待整理全文查看、容量行为统一、手动日历冲突提示等现有体验缺口，建议优先于扩展更多 Agent。

以上属于后续决策，不阻塞本文件交付，也不表示已经授权全部实施。

## 15. 附录与来源

### 15.1 术语

| 术语 | 含义 |
|---|---|
| 待整理 | 暂存未归类或待确认内容的本地列表，不是邮箱 |
| 待办 | 需要完成或跟进的事情，可以没有截止日期 |
| 截止日期 | 最晚完成时间，允许只有日期精度 |
| 日历安排 | 实际执行时间或用户主动选择的全天事件 |
| 主助手 | 统一处理入口与流程调度，不等同无限自主运行的模型 |
| 专业流程 | 具有明确输入、输出、校验和确认步骤的会议/排程工作流 |
| ASR | 语音识别，将音频转成文本 |
| OCR | 图像文字识别 |
| 幂等 | 同一操作重复提交不会产生重复副作用 |
| 预览确认 | 候选结果与真实写入分开，由用户决定是否执行 |
